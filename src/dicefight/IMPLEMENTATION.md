# 더 다이스 파이트 — 구현 및 실행 안내

## 완료 범위
기존 .NET 9 Windows Forms 프로젝트를 유지하여 메인 → 주사위 4단계 → 카운트다운 → 대전 → 결과 → 재대결을 구현했습니다. 온라인, AI, 콤보, 캐릭터 선택은 없습니다. 양측은 같은 캐릭터의 색상 변형과 동일한 이동/공격 판정을 사용합니다.

확정 공식: 공격력 = 4 + 두 눈의 곱(5~40), 최대 체력 = 64 + 두 눈의 곱(65~100). 각 단계에서 독립적인 두 눈을 새로 추첨합니다. 낮은 체력으로 한 번에 끝나는 경우도 그대로 허용합니다. 결과를 확인한 다음 버튼으로 다음 단계로 진행합니다.

## 열기와 실행
- `src/dicefight/dicefight.sln`을 Visual Studio 2022로 열고 dicefight를 시작 프로젝트로 지정한 뒤 F5 또는 Ctrl+F5.
- 조사된 설치 버전은 VS 2022 17.14.40, .NET SDK 9.0.318입니다. 대상은 원본 그대로 `net9.0-windows7.0`입니다. 이는 실제 Windows 7 지원을 보장한다는 뜻은 아닙니다.
- .NET 데스크톱 개발 워크로드와 .NET 9 SDK가 필요합니다. 프로젝트의 global.json은 9.0.3xx SDK를 선택해 .NET 10이 기본 선택되는 것을 방지합니다.
- `bin/Release/net9.0-windows7.0/dicefight.exe`로 실행할 수도 있습니다. 배포 시 exe 하나만 복사하지 말고 DLL 및 resource를 포함한 출력 폴더 전체를 복사하세요. 실행 PC에는 .NET 9 Windows Desktop Runtime이 필요합니다.
- 일반 명령줄: 프로젝트 폴더에서 `dotnet restore`, `dotnet build -c Release`, `dotnet run -c Release`.
- 이 작업 환경의 외부 NuGet 접속은 실패하여 이미 설치된 로컬 캐시로 복원했습니다. 패키지의 이름/버전은 변경하지 않았습니다.

## 조작
| 동작 | 1P (파랑) | 2P (빨강) |
|---|---|---|
| 좌우 | A / D | ← / → |
| 점프 | Space | 숫자패드 0 |
| 웅크리기 | S 유지 | ↓ 유지 |
| 중단 | J | 숫자패드 . |
| 상단 | W + J | ↑ + 숫자패드 . |
| 하단 | S + J | ↓ + 숫자패드 . |

공격/점프는 새로 누르는 순간에만 발생합니다. 상·하를 함께 누르면 중단, 좌·우를 함께 누르면 정지합니다. 점프와 공격이 동시에 들어오면 점프를 우선합니다. 공격 중에는 이동/점프가 잠기며 공중 공격과 이단 점프는 없습니다. 창 전환 시 일시정지하고 입력을 비웁니다. 돌아오면 키를 다시 눌러야 합니다.

숫자패드 0/소수점은 Windows 물리 스캔 코드 0x52/0x53으로 식별하므로 Num Lock Off에서도 동일하게 처리합니다. 일반 마침표(0x34)와 별도 Delete/Insert(확장 비트)는 다릅니다. 실제 키보드 드라이버/원격 접속에 따라 달라질 수 있어 Num Lock On/Off 플레이 점검이 필요합니다. 키보드 고스팅/동시입력 제한은 소프트웨어로 해제할 수 없습니다. 두 플레이어가 이동+높이+공격을 함께 눌러 확인하세요.

## 코드 역할
- Program.cs: 시작점, --self-test와 --smoke 검증 모드.
- GameForm.cs: 화면 렌더링, 마우스 버튼, 창 이벤트, 물리 루프 연결. 별도 게임 엔진 없음.
- GameSession.cs: 주사위와 화면 전환, 재대결, 고정 시간 누적기.
- KeyboardInput.cs: 물리 키 식별, 두 플레이어 입력, 새 누름/해제 관리.
- Combat.cs: 캐릭터 상태, 물리 이동, 공격 영역, 상쇄·피해·승패 일괄 판정.
- GameBalance.cs: 공식과 모든 전투/시간/경기장 설정. 단위는 주석 참조.
- Resources.cs: 리소스 경로/애니메이션 설정, 캐시, 누락 대체, BGM.
- SelfTests.cs: 실제 게임 로직과 렌더러를 호출하는 자동 검증.
- glc2d/: 설치된 glc2dcsharp 0.1.0.8 패키지가 제공하는 원본 소스. 패키지 예제를 조사했으나 실제 화면은 WinForms, 음악은 NAudio AudioFileReader/WaveOut을 사용합니다. glc2d 오디오 경로의 종료 오류를 피하기 위해 직접 NAudio 재생으로 교체했습니다.
- GameMain.cs / GameGlobal.cs / AppMain.cs: 패키지 자동 생성 예제. 실제 시작점은 Program이며 예제 GameMain은 실행하지 않습니다.
- Program.cs.original: 변경 전 사용자 시작 코드 보존본.

## 전투 판정의 정확한 의미와 임시 정책
120 Hz 고정 물리 틱마다 양쪽 입력을 수집한 후 양쪽 피해 후보를 계산합니다. 같은 틱에서 시작한 공격을 동시 공격으로 정의합니다(약 8.33ms 정밀도). 준비·유효·후딜은 모두 초 단위이며 렌더링 프레임 수와 무관합니다. 오래 멈춘 뒤 최대 0.1초만 누적하고 포커스 상실 시 시간 누적을 비웁니다.

공격 방향은 시작 순간 고정됩니다. 공격 사각형이 상대 몸 사각형과 겹쳐야 적중합니다. 점프의 실제 몸 위치로 검사합니다. 한 공격은 적중/상쇄 후 소모되어 재적중하지 않습니다. 같은 높이이고 시작 시각 차이가 0.09초 이하이며 양측 공격이 서로 닿는 거리/높이이면, 먼저 유효해지는 순간 상쇄합니다. 이때 상대의 준비 중 공격도 상쇄에 참여합니다. 멀리서 버튼만 누르면 상쇄하지 않습니다. 상쇄 후 남은 후딜은 유지됩니다.

다른 높이는 유효 사거리에서 먼저 유효해진 공격이 적중합니다. 피해는 공격자의 공격력 그대로이며 피격 시 진행 중 공격을 취소합니다. 빗나간 선공은 우선권을 예약하지 않습니다. 동일 틱에 시작한 다른 높이 공격은 양측 피해를 먼저 계산하여 함께 적용하며, 양측 HP가 0이면 무승부입니다. 처리 배열의 1P/2P 순서는 피해 우선권이 아닙니다.

`GameBalance` 임시 초기값:
| 항목 | 값 |
|---|---|
| 이동 | 280 px/s |
| 점프 초기속도 / 중력 | 840 px/s / 1800 px/s² |
| 몸 상자 | 64 × 154 px |
| 몸 앞 사거리 / 공격 두께 | 100 px / 38 px |
| 발 기준 상/중/하 중심 | 130 / 82 / 27 px |
| 준비 / 유효 / 후딜 | 0.15 / 0.10 / 0.30초 |
| 상쇄 허용 차이 | 0.09초 |
| 넉백 속도 / 감속 | 340 px/s / 1100 px/s² |
| 피격 경직 | 0.24초 |
| 주사위 / 카운트다운 | 1.1초 / 3초 |
| 논리 화면 / 바닥 | 1200×720 / y=600 |
| 몸 중심 경계 | x=45~1155 |

`CancelAttackOnHit`, `SimultaneousDifferentHeightTrades`, `DoubleKnockoutIsDraw`가 임시 정책 스위치입니다. 동시 피해를 false로 바꾸면 동시 교환의 양쪽 피해를 모두 취소합니다. 동시 KO 무승부를 false로 바꾸면 최대 체력이 높은 쪽 승리, 같으면 무승부입니다. 주사위 공식은 확정 사항이므로 현 요청대로 유지했습니다.

## 리소스 연결과 교체
실행 파일 기준 `resource/`만 사용하며 csproj에서 하위 폴더까지 출력/게시 폴더로 복사합니다. 원본 이미지/음악을 변경하지 않았고 외부 다운로드도 하지 않았습니다.

| 용도 | 실제 파일/폴더 |
|---|---|
| 메인/주사위/경기장 | bcakground/mainground.png, diceground.png, battleground.png |
| 주사위 눈 | dice/faces/face_1.png ~ face_6.png |
| 회전 | dice/rotation/rotation_01.png ~ rotation_12.png |
| 제목/승리 | logo/title.png, bluewin.png, redwin.png |
| 캐릭터 | team blue 및 team red 아래 상태별 frame_01.png ~ frame_06.png |
| 음악 | bgm/Asian_Drums-Kevin_Maclead.mp3 |

`bcakground`는 실제 폴더의 오타를 보존했습니다. 상태는 01_idle, 02_move_right, 04_attack_middle, 05_attack_high, 06_attack_low, 07_jump, 08_duck, 09_ground_hit, 11_defeat를 사용합니다. 왼쪽 방향은 원본 오른쪽 프레임을 반전합니다. 03_move_left, 10_air_hit 및 sheet.png는 현재 별도 사용하지 않습니다. 시작 버튼 이미지 gamestart.png는 존재하나 일관된 읽기 쉬운 텍스트 버튼을 그립니다.

이미지 전체 크기 목록은 docs/resource-inventory.txt에 있습니다. 주사위 눈 295~296px, 회전 362px, 캐릭터는 181×181, 362×724 등 상태별 크기가 다릅니다. 피격 sheet.png는 6열×1행(2172×724), 패배 sheet.png는 3열×2행(1536×1024)의 6프레임이며, 현재는 이미 분리된 frame 파일을 사용합니다. 투명 여백은 런타임에만 잘라 발 위치를 맞춥니다. 원본이 불투명 배경을 포함하면 해당 배경도 그대로 표시됩니다.

교체할 때 Resources.cs의 ResourceMap 경로, Frames(6), RotationFrames(12), FramesPerSecond(10), IdleFramesPerSecond(3), WalkCycleDistance(140px), CrouchFrame(3), SourceFacing(1)을 수정하세요. 새 이미지 파일도 resource에 넣으면 자동 복사됩니다. 현재 없는 것은 타격/상쇄/주사위 효과음, 별도 무승부·재대결 UI 이미지입니다. 효과음은 생략하고 UI는 텍스트로 그립니다. 캐릭터·주사위·배경·로고가 빠지면 각각 색상 도형·숫자·단색 바닥·텍스트로 대체합니다. 음악이나 출력 장치가 없으면 무음으로 계속합니다. Resources.Missing에서 누락/재생 실패를 확인할 수 있습니다.

## 검증과 남은 확인
자동 검증: 20개 시나리오(주사위 공식/순서, 동시입력 모델, 선공/상쇄/늦은 입력/거리, 공중공격 차단, 점프 넘기, 경계, 한 번 피해, 승리/무승부, 재대결, FPS 독립, 누락 리소스, 전체 화면 렌더링). `dicefight.exe --self-test` 실행 시 self-test-results.txt와 verification 폴더에 결과를 기록합니다. 화면 캡처는 실제 게임 렌더러 출력이며 사람이 조작한 플레이 영상은 아닙니다.

`--smoke`는 실제 WinForms 메시지 루프와 창 생성/화면 출력/정상 종료를 확인합니다. 음악 재생 경로도 실행하지만 귀로 음질이나 볼륨을 확인한 것은 아닙니다. 창을 수동으로 조작한 전체 2인 플레이 및 Visual Studio GUI에서 F5를 누르는 과정은 자동 검증과 구분해야 합니다.

사람이 남겨서 확인할 항목: 실제 두 사람이 모든 키를 동시에 누르기, Num Lock On/Off, 창 전환 후 키 재입력, 모니터 배율별 가독성, 음악 음량, 체감 사거리/상쇄 타이밍, 원본 프레임의 자세 전환 품질. 일부 원본 프레임의 여백/자세 차이로 시각적 크기 변화가 있을 수 있으며 판정 상자는 고정입니다.



최종 실행 검사: Visual Studio 2022에 설치된 MSBuild로 Release 솔루션 빌드 성공. dotnet 최종 빌드 경고 0/오류 0. 정상 리소스/전체 리소스 누락 각각 자동 검증 20/20. 실제 창 메시지 루프 검사는 종료 코드 0. 음악 초기화는 별도 배경 스레드에서 수행하여 장치/코덱 응답 지연이 게임을 멈추지 않게 했습니다. 실제 소리가 들리는지는 수동 확인이 필요합니다.

## 이번 수정: 능력치·자세·애니메이션
능력치 계산식은 화면에 표시하지 않고 확정 수치만 표시합니다. 점프는 Space/숫자패드0을 새로 누를 때만 발생하며 W/↑는 점프하지 않습니다. S/↓는 누르는 동안 웅크립니다. W/↑를 누른 상태에서 공격하면 상단 공격입니다. 이미 점프한 뒤에는 원래 규칙대로 공중 공격을 할 수 없습니다. 별도 점프 키와 공격을 동시에 누르면 기존처럼 점프 우선입니다.
웅크리기는 정지 자세이며 몸 높이는 GameBalance.CrouchHeight=92px입니다. 상단을 피할 수 있지만 중단·하단은 적중합니다. 원본 08_duck의 4번째 자세를 유지하며 해제 시 일어납니다.
걷기는 실제 이동 거리 140px마다 6프레임 한 주기로 재생합니다. 이동 속도를 바꾸면 보행 속도도 함께 변하고 벽/상대에게 막히면 발 움직임도 멈춥니다. ResourceMap.WalkCycleDistance를 늘리면 보폭이 길어지고 발 움직임은 느려집니다.
대기 호흡은 초당 3프레임으로 앞뒤 왕복하여 약 3.33초에 한 호흡을 재생합니다. IdleFramesPerSecond를 낮추면 더 느려집니다. 이전의 모든 상태 공통 10fps에서 분리했습니다.
새 공식, 키 배치, 웅크림과 상단 회피, 이동 거리 기반 프레임 및 느린 호흡 검증을 포함해 23개 검사를 수행합니다.


## 12프레임 및 전투 효과 반영
- 캐릭터 Frames=12, 일반 동작 20fps. 대기 모션은 3.6fps 순방향 반복으로 약 3.33초 호흡을 유지합니다. 걷기는 140px당 12프레임이며 뒤로 이동하면 12_backwalk를 사용합니다.
- 웅크리기는 새 모션의 7번째 프레임(인덱스 6)까지 재생 후 유지합니다. 피격·점프·패배는 상태 진입 시 첫 프레임부터 재생하며 마지막 프레임에서 멈춥니다. 공격은 기존 공격 지속시간에 12장을 배분합니다.
- 머리 위 상/중/하단·준비/공격/후딜 글자와 임시 공격 영역 사각형은 제거했습니다.
- 상쇄 글자 대신 logo/cancel.png를 0.55초 표시합니다.
- 실제 피해가 확정된 교차 영역에 effects/shockwave/frame_01~12.png를 32fps로 약 0.375초 단발 재생합니다. 헛스윙과 상쇄에는 발생하지 않습니다. 동시 피해는 각 적중 위치에 하나씩 표시합니다. KO 이후에도 효과 시간이 진행되며 재대결하면 초기화됩니다.
- 효과 경로, 크기(140px), 프레임 수, fps는 Resources.cs의 ResourceMap에서 수정합니다. 기존 logo/effects/shockwave의 6장은 사용하지 않습니다. 원본 리소스의 백업 폴더는 보존하며 새 빌드 복사 대상에서 제외했습니다.
